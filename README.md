# Формирование отчётов

Windows-приложение для аналитиков по управлению товарными запасами. Задачи выбираются
в списке слева, у каждой свой файл на входе и своя книга на выходе:

- **План склада** — из вчерашнего файла плана и двух свежих выгрузок («Заказы на отгрузку»
  и «Журнал заказов на отгрузку») формирует сегодняшний лист «План»;
- **Распред** — из инвойса, прайсов, остатков и регламента наценок заполняет листы
  «для цен», «Цены», «остатки», «Распред» и «Загрузочник» книги распреда; идёт двумя
  этапами, подготовкой и пересчётом;
- **Подтоварка МП** — по заявке маркетплейса разбирает колонку «Запрет», заполняет
  «Заметку» и собирает лист «Согласовать», а затем расставляет места хранения и собирает
  листы «из‹место›» и загрузочники;
- **Приемка на хранилище** — разбирает выгрузки остатков, склада и приходов, собирает
  листы поставок и «итог», а после того как аналитик решит «Допоставить», — адреса и тары;
  идёт двумя этапами, подготовкой и адресами;
- **Обновления** — программа сама проверяет, не вышла ли новая версия, и ставит её в один щелчок.

Окно есть в светлой и тёмной темах - каждая своя целиком, включая боковую панель
и заголовок окна. Переключатель - маленькая кнопка внизу панели, выбор запоминается
до следующего запуска.

Приложение автоматизирует установленный на компьютере Microsoft Excel, поэтому в результате
полностью сохраняются формулы, форматирование, объединённые ячейки, условное форматирование,
числовые форматы и высоты строк исходной книги.

---

## Требования

- Windows 10 или Windows 11, 64 бита;
- установленный Microsoft Excel — 2016, 2019, **2021** или Microsoft 365;
- права администратора **не нужны**;
- отдельно устанавливать .NET **не нужно**.

Версия Excel значения не имеет: программа обращается к нему через позднее связывание,
без привязки к библиотекам типов конкретного выпуска Office.

---

## Как получить готовую программу

Официальная сборка выполняется в GitHub Actions. Собирать что-либо у себя не нужно.

1. Откройте раздел **Releases** репозитория.
2. Скачайте единственный файл `WarehousePlanAutomation-<версия>-win-x64.exe`.
3. Запустите его.

Установка и распаковка не требуются: это один самодостаточный исполняемый файл,
внутри которого уже лежит нужная версия .NET.

При первом запуске Windows SmartScreen может предупредить о неизвестном издателе —
файл не подписан сертификатом. Нажмите «Подробнее» → «Выполнить в любом случае».

Если релиз ещё не выпущен, тот же .exe можно скачать из вкладки **Actions**: откройте последний
успешный запуск workflow **Release** и заберите артефакт `WarehousePlanAutomation-win-x64`.

## Как работать

1. Выберите задачу в списке слева.
2. Подготовьте книгу — что в ней должно быть свежим, написано под заголовком задачи.
   Листы ищутся по началу названия, поэтому дописать к нему дату или пометку можно:
   «Заказы на отгрузку 04_09» и «Журнал заказов на отгрузку тест» находятся так же.
   Важно только, чтобы под одно название подходил ровно один лист.
3. Нажмите **«Выбрать файл»** — или просто перетащите книгу в окно.
4. Нажмите кнопку запуска.
5. Дождитесь окончания обработки. Кнопка запуска на это время блокируется, интерфейс не зависает,
   рядом появляется **«Отмена»**: длинную обработку большого файла можно прервать.
6. После успешного завершения появятся счётчики, список замечаний и полный путь к результату.
   Кнопка **«Открыть папку с результатом»** покажет файл в проводнике.

### На что смотреть в результате

Счётчик, который требует действия, окрашивается — остальные просто сообщают, что программа
сделала. Под счётчиками список **«Что проверить руками»**: каждое замечание говорит, что
именно не сошлось и в каком месте книги. Если замечаний нет, там так и написано.

Кнопка **«Открыть в Excel»** в карточке результата открывает готовую книгу сразу.
Если она уже открыта, программа переходит в неё же, а не открывает вторую копию.

Сразу после выбора файла программа осматривает книгу - за доли секунды, без Excel -
и говорит, все ли нужные листы на месте и доступны ли связанные файлы (стенки,
согласованные цены). Так о непорядке видно до запуска, а не через полминуты.
Диалог выбора файла открывается там же, где книгу брали в прошлый раз; у каждой задачи
своя папка.

**По замечанию можно щёлкнуть** — готовая книга откроется, и курсор встанет ровно на ту
ячейку, о которой речь. Если книга уже открыта, программа переходит в неё же, а не открывает
вторую копию. У общих замечаний, не привязанных к месту, переход не работает: такая строка
просто не подсвечивается под курсором.

Иногда программа останавливается и спрашивает. Это значит, что правило допускает несколько
ответов, а выбор зависит от того, что за товар в поставке, — например, в «Регламенте наценок»
для сектора «ОБУВЬ» пять строк: зима, лето, деми, всесезон, тапочки. Программа такое
не угадывает. Можно нажать **«Пропустить»** — тогда ячейки останутся пустыми, а в замечаниях
появится строка о том, что выбор не сделан.

### Где появляется результат

Рядом с исходным файлом, в той же папке. К имени книги добавляется, что с ней сделали,
и когда:

```
<исходное имя> план склада ГГГГ-ММ-ДД_ЧЧММ.<расширение>
<исходное имя> подготовка ГГГГ-ММ-ДД_ЧЧММ.<расширение>
<исходное имя> распред ГГГГ-ММ-ДД_ЧЧММ.<расширение>
<исходное имя> подтоварка ГГГГ-ММ-ДД_ЧЧММ.<расширение>
<исходное имя> приемка ГГГГ-ММ-ДД_ЧЧММ.<расширение>
<исходное имя> адреса ГГГГ-ММ-ДД_ЧЧММ.<расширение>
```

Отметка прошлого запуска при этом снимается: распред идёт двумя этапами, и файл второго
делается из файла первого — иначе имена накапливались бы. «Поставка подготовка …»
на втором этапе становится «Поставка распред …», а не «Поставка подготовка … распред …».

**Исходный файл никогда не изменяется.** Все действия выполняются только над копией.
Если во время обработки возникает ошибка, Excel закрывается, повреждённая копия удаляется,
а в окне появляется понятное сообщение.

### Что нужно проверить вручную

На листе «Заказы на отгрузку» результата остаются только строки, которые **не** удалось
распределить автоматически: у них нет номера загрузки и они не попадают ни под одно правило.
Их нужно разобрать руками. Все обработанные строки с листа удаляются физически.

Лист «Журнал заказов на отгрузку» программа только читает и никогда не сортирует и не меняет.
Остальные листы книги не затрагиваются.

## План склада

Порядок обработки зафиксирован и не настраивается:

1. **«Опт»** — строки, у которых «Подразделение» содержит «Опт»: сумма «разница единиц»
   записывается в строку «заказы Опт», строки удаляются.
2. **«777»** — аналогично, сумма попадает в «заказы ИМ».
3. **Маркетплейсы** — Озон/Ozon, ВБ/WB/Wildberries, Ламода/Lamoda, Сбер/Sber,
   Екатеринбург Яблоко, Магнит. Строго в таком порядке:
   - комментарий содержит «возвр» → «заказы МП» / «из возвратов»;
   - в комментарии найден номер поставки → «заказы МП» / «из поставок»;
   - все остальные → «заказы МП» / «с хранилища и хранения».
4. **Документы «ЗП»** — оставшиеся строки, в комментарии которых есть «ЗП»
   («ЗП373-1739»), просто удаляются: в план они не переносятся, даже если номер загрузки
   в комментарии есть.
5. **Служебные строки** — оставшиеся строки, чей комментарий содержит
   «автозаказ», «вирт», «виртуал», «фото», «образцы», «ремонт», «списать» или «маркировка»,
   просто удаляются, никуда не перенося суммы.
6. **Реальные заказы** — из комментария извлекается число после слов «Номер загрузки», строки
   группируются по этому номеру, суммы попадают в «Количество единиц» соответствующего заказа.
7. **Новые заказы.** Если в «Плане» уже есть строка **без** номера загрузки, чья «Поставки»
   совпадает с текстом нового заказа, номер вписывается в неё: так аналитик планирует поставку
   заранее, и второй такой же строки быть не должно. Иначе строка добавляется копированием
   существующей строки того же блока средствами Excel, чтобы наследовать формулы и оформление:
   - в блок **«приемка на хранилище»**, если в тексте есть «приемка» («приёмка»);
   - в блок **«возвраты»**, если в тексте есть «возвр»;
   - в **«все группы»** — всё остальное.

   «Приемка» проверяется раньше «возврата»: заказ «…_получение в рознице 01.10_приемка
   на хранилище из возвратов» стоит в плане в блоке приемки, хотя «возвратов» в нём тоже есть.

   **Дата в тексте новой строки** — «2452-010,014 Угги, кеды СЕТ 1 для Юга_в рознице с 15.10» —
   выделяется в «Поставках» красным и встаёт в «Дату в сети» значением вместо формулы.
   Год берётся тот, при котором дата ближе всего к дате документа: «15.01» у заказа
   от 20 декабря — это январь следующего года. Дату, совпадающую с датой документа, программа
   датой в сети не считает: в «Срочная подтоварка 28.08_Хранение» 28.08 — день, когда завели
   заказ, и у таких строк «Дата в сети» в плане считается формулой.

   **«Дней в работе», «Дата в сети», «Дата отгрузки» и «Решение»** у новой строки считаются
   формулами, как у остальных. Если у строки-образца в какой-то из этих колонок стояло
   значение, формула берётся у ближайшей строки заказа, где она есть (сначала в том же блоке),
   и переносится так же, как при протягивании.

   **Срочная подтоварка** («Срочная подтоварка 28.08_Хранение») должна быть в сети на 4 дня
   раньше: у новой такой строки «Дата в сети» считается как «=F5+$O$2-4», у остальных —
   «=F5+$O$2». Формула взята у соседней строки, поэтому «-4» в ней сначала убирается и ставится
   заново по тексту самой строки: и «срочная», и «подтоварка». «…_срочная отгрузка» под правило
   не попадает.
8. **Журнал** задаёт «статус» и «% выполнения» (как считается процент — ниже).
   Если номера загрузки в журнале нет вообще, «Количество единиц» становится 0, а «статус»
   и «% выполнения» остаются прежними. Столько же — 0 — получает заказ, который есть во
   вчерашнем «Плане», но пропал из сегодняшней выгрузки; его «Номер загрузки» дополнительно
   закрашивается розовым, чтобы строку было видно и можно было убрать вручную.
   У строк, добавленных сегодня, «Номер загрузки» закрашивается зелёным. При следующем запуске
   обе пометки снимаются: вчерашнее «сегодня» уже не новость.
9. **«автозаказы для хабов»**: пн — 24000, вт — 18000, ср — 12000, чт — 6000, пт — 42000,
   в субботу и воскресенье значение не меняется.
10. **Сквозная нумерация «№»** внутри каждого блока реальных заказов. Порядок строк
    при этом не меняется: новые строки уже стоят внизу своего блока.

### Как считается «% выполнения»

Не по колонке «%» журнала: там процент отдельного документа, а не заказа целиком.
Процент собирается из «Кол-во ед» и «Факт ед»:

```
% выполнения = округлить( Σ«Факт ед» / Σ«Кол-во ед» × 100 )
```

Суммируются только строки-документы заказа, каждый номер документа — один раз.
Отбрасывать приходится две вещи:

- **сводные строки.** В колонке «Номер» у них стоит не документ («З000-760355»), а число
  («-21»). Их «Кол-во ед» уже включает строки магазинов, и при суммировании всё удвоилось бы;
- **повторы.** Лист журнала — несколько подряд приклеенных выгрузок: в разобранном файле
  107 007 строк при 14 222 уникальных номерах документов. Закрытые заказы повторяются чаще
  новых, поэтому без дедупликации итог перекашивается в их пользу.

Пример из реальной книги: заказ 44388195, закрытая группа 8046 из 8046 плюс запущенная
2308 из 15427 — итого 10 354 из 23 473, то есть 44 %. Числа 44 в колонке «%» журнала нет
ни в одной из 202 его строк, а по первому вхождению получилось бы 100 %.

## Распред

Распред разделён на два этапа, и в боковой панели это два пункта. Между ними человек
делает то, чего программа сделать не может: протягивает колонки со стенками из файлов
в сетевых папках.

| Этап | Что берёт на входе | Что делает |
|---|---|---|
| **Распред · подготовка** | предыдущая книга распреда со свежими «Invoice», «Сводный прайс», «Прайс по подразделениям» | листы «для цен» и «Цены»: строки, справочные колонки, фотографии из инвойса |
| **Распред · пересчёт** | файл после подготовки, в котором уже протянуты стенки; свежие «link», «Остатки Н», «КС», «Аналоги», «Регламент наценок»; по желанию — папка согласования цен | наценки, «Аналог гугл», «Согласованные цены», проверки по стенкам и «link», листы «остатки», «Распред», «Загрузочник»; листы книги не удаляются |

Каждый этап проверяет книгу до запуска только на свои листы: пересчёту инвойс уже
не нужен, а подготовке — «Остатки Н». Папку каждый пункт запоминает свою.

**Один файл — один сектор.** В инвойсе сектор не написан: он появляется только на листе
«Цены», когда строки подтянуты из «Сводного прайса». Если секторов оказалось несколько,
нужный узнаётся по названию файла — поставка так и называется, «C2518-084 Бижутерия
LTL719.xlsx». Подходит сектор, у которого хотя бы одно слово названия стоит в имени файла
отдельным словом: «КОЛГОТКИ,НОСКИ» находится по файлу «318-140 Носки FTL 36». Если
по названию не решить — программа спрашивает. Строки остальных секторов в файл не попадают,
для них нужен отдельный запуск на той же исходной книге; итоги «для цен» считаются
по оставшимся строкам.

### Листы «для цен» и «Цены» (подготовка)

1. **Читает инвойс.** Строка заголовков находится по «штрих-код / количество / цена / сумма».
   Второй строкой заголовков на английском и строкой «итого» она не обманывается: строкой
   товара считается только та, где есть штрихкод и «количество» — число.
   **Инвойсов бывает несколько** — лист на каждую поставку: «Invoice-338», «Invoice-341».
   Берутся все листы, название которых начинается с «Invoice», в порядке книги; при выборе
   файла несколько таких листов помехой не считаются. Номер поставки берётся из шапки
   («Инвойс № и дата»). Если его там нет, он ищется по названиям: последнее число
   в названии листа («341») и номер в названии файла, который им кончается
   («431-338, 431-341 Бижутерия» → «431-341»). Не подошёл ни один или подошли два —
   колонка «Поставка» остаётся пустой, и об этом пишется замечание.
2. **Заполняет «для цен»**: «Поставка», «Количество», «Сумма закупа». «Рублевая оплата»,
   «Курс» и «Логистика» не трогаются — их вносит человек, и от них зависят формулы
   «% логистики» и «Фактический курс». Колонок на листе становится ровно столько, сколько
   инвойсов: недостающая создаётся копией первой — вместе с формулами «Курс»
   и «% логистики», — а лишняя очищается целиком. В прошлом файле поставок могло быть две,
   а в этом одна: её цифры остались бы на листе и попали бы в отчёт. Ссылки строк «Цены»
   на «для цен» переводятся на нужную колонку в обе стороны.
3. **Доводит число строк «Цены» до числа штрихкодов.** Новые строки создаются копией первой
   строки данных, поэтому наследуют все её формулы и оформление. Строки, которые уже стояли
   в заготовке, приводятся к первой: после прошлого распреда одна строка бывает заполнена,
   а вторая пустая, и без этого во второй не было бы ни одной формулы. Недостающие формулы
   копируются из первой строки (вписывать их нельзя: вписанную СРЗНАЧЕСЛИ по стотысячному
   «прайсу» Excel считает секунды на ячейку), оформление переносится, высота строк у всех
   одна — не ниже 63,75, чтобы было где стоять фотографии.
   **Формулы под таблицей** — итоговая строка и всё, что ниже, до 50 строк, — растягиваются
   на все строки данных: «=SUM(P2:P3)» после добавления строк становится «=SUM(P2:P15)».
   Растягиваются только диапазоны, которые начинаются с первой строки данных и кончаются
   внутри таблицы; ссылки на другие листы и на строки под таблицей не трогаются.
   **Перед заполнением на «Сводном прайсе» колонка «Штрихкод» выносится в начало листа**,
   как в инструкции: по ней ищут ВПР, а ВПР ищет только в первой колонке диапазона. Колонка
   переезжает целиком, вырезанием, без буфера обмена; ссылки на её ячейки идут за ней.
   Если «Штрихкод» уже первый, ничего не меняется.
4. **Заполняет строки**: «Копия ШК», «Ед.», «Мах_Закуп», «Сумма_закупа», «цена_закупочная»,
   «Поставка» — из инвойса. Если штрихкод в инвойсе повторяется, в «цена_закупочная» каждой
   повторки пишется сумма их «Мах_Закуп» — так требует инструкция; строки остаются
   подсвеченными. «КОД», «модель», «Сектор», «Группа», «наименование», «артикул»,
   «цвет», «сезон», «размер» — из «Сводного прайса» по штрихкоду; «Подгруппа» —
   из «Прайса по подразделениям» по коду.
5. **Переносит фотографии из инвойса** — в колонку «артикул» той строки, куда попал этот
   штрихкод, в правый нижний угол ячейки: по инструкции артикул не должен быть закрыт,
   и над картинкой остаётся строка текста. Все фотографии вписываются в одну рамку — ширина
   ячейки на высоту строки без строки текста. В инвойсе картинки бывают любого размера
   и растянуты по одной стороне; перед вписыванием им возвращаются исходные пропорции снимка.
   Если Excel не вставил картинку с первого раза (буфер обмена занят другой программой),
   вставка повторяется. Картинки прошлой поставки с листа сначала удаляются: при копировании
   строки-образца они бы ещё и размножились. Бывает, что фотография в инвойсе одна
   на артикул, а размеры и цвета идут строками ниже без картинки, — такие строки получают
   фотографию своего артикула, сначала того же цвета. Если фотографии нет и у артикула,
   строка попадает в замечания.
   **Буфер обмена проверяется.** Он общий на весь компьютер: рядом открыт Excel, мессенджер,
   удалённый рабочий стол. Если копирование не дошло до буфера, вставка брала то, что лежало
   в нём раньше, — и во всех блоках «Распреда» оказывалась одна и та же чужая фотография.
   Теперь буфер перед копированием очищается, после копирования программа проверяет, что
   в нём её картинка, а вставленную сверяет по размеру с исходной; не сошлось — удаляет
   и повторяет. В заголовках блоков «Распреда» перед вставкой удаляются все старые картинки,
   которые туда заходят, в том числе вставленные макросом по ссылке.
6. **Очищает** «Согласованная наценка по поставке», «Согласованная мин наценка на арт»,
   «Ком КМ», «Ком Баера», «Решение», «Линк» и «Проверка запретов» — их заполняют по ходу
   разбора либо на втором этапе, и с прошлой поставки в них ничего оставаться не должно.
7. **Подсвечивает розовым** то, что видно без стенок: ненайденный штрихкод и повтор.
8. **Выделяет одинаковые штрихкоды цветом.** В «Копия ШК» строки с одним и тем же
   штрихкодом заливаются одним цветом, у каждой группы повторов свой — голубой, жёлтый,
   сиреневый, персиковый и дальше по кругу. Так пары видно сразу, в том числе когда
   повторы пришли из разных инвойсов. Выделение ставится и на пересчёте, по тому, что
   стоит на листе. Оттенки взяты чуть в стороне от стандартной палитры Excel: при
   следующем запуске программа снимает их как свои, а ячейку, которую аналитик покрасила
   сама, не трогает.

### Что пересчитать

На странице «Распред · пересчёт» над кнопкой запуска — выбор из трёх вариантов:

| Вариант | Когда | Что делает |
|---|---|---|
| **Весь файл** | обычный пересчёт после подготовки | всё, что описано ниже: наценки, аналоги, согласованные цены, проверки, «остатки», «Распред», «Загрузочник» |
| **Только link** | обновили лист «link» | заново сверяет «Цены» с «link»: «Линк», «Проверка запретов», даты и грейды, подсветка и повторы штрихкодов. Наценки, цены и остальные листы не трогаются |
| **Только остатки** | обновили «Остатки Н» | заново собирает «остатки», переставляет на них ссылки «Распреда», возвращает «мин запас на Хаб» к общей настройке и заново применяет правило 30 %, сортирует РТТ и проверяет загрузочник. Блоки, фотографии, сезонность и «Цены» не трогаются |

Надпись на кнопке меняется вместе с выбором. Выбор не запоминается между запусками
программы: по умолчанию всегда «Весь файл» — неполный пересчёт по ошибке хуже лишнего щелчка.

«Мин запас на Хаб», обнулённый прошлым пересчётом, теперь возвращается к общей настройке
и при полном пересчёте — перед тем как первый блок размножается на остальные. Иначе ноль
первого блока разошёлся бы по всем. Возвращаются только нули: другое число вписал человек.

### Проверки (пересчёт)

Второй этап работает по тому, что уже стоит на листе «Цены»: инвойс и справочники
не читаются, строки берутся с самого листа — часть колонок человек к этому времени
поправил руками.

- **Ставит наценки** из «Регламента наценок». Наценка берётся на каждую подгруппу своя:
  в одной поставке подгрупп бывает несколько, и регламент для них разный. Если сектор
  в регламенте встречается один раз — без вопросов. Если строк несколько, строка выбирается
  по подгруппе, а если по подгруппе не нашлась — берётся «Прочее», как написано в инструкции.
  «Сектор+» пишется сокращениями («МЕЛ АКСЕСС под упак», «ШАРФЫ И ПЛАТКИлето»), поэтому
  сравниваются слова, которыми строка отличается от сектора: «рюкзак», «кошелек», «рукавицы»,
  «тапочки»; в подгруппе слово может стоять и в другой форме («КОШЕЛЬКИ»). «Прочее» — это строка
  «ПРОЧЕЕ» или «СУМКИ прочее», а также строка, совпадающая с самим сектором («ПЕРЧАТКИ»).
  В примере маска для сна получает наценку «ПРОЧЕЕ», как и у аналитика. Спрашивает программа
  только там, где ответа нет и так: у «ОБУВЬ зима / лето / деми» ни подгруппа, ни «Прочее»
  выбора не дают. Наценки ставятся на втором этапе потому, что к нему подгруппы уже проставлены
  и видно, сколько их. Там, где регламент ответа не даёт, ячейки остаются как были:
  наценку в них мог вписать человек, и повторный пересчёт её не стирает.
- **Заполняет «Аналог гугл»** по листу «Аналоги». Вручную это два ВПР против «Всп», фильтры,
  зелёная заливка и перенос строк в колонки J и K; итог процедуры программа считает сразу.
  Аналог есть у АЦ поставки, который стоит на листе справа, в колонке «Аналог», если АЦ слева
  в этой строке в поставку не входит; аналогом тогда пишется АЦ слева. Остальным — «нет».
  Колонка пишется значениями. Если листа «Аналоги» нет, колонка остаётся как была.
- **Проставляет «Согласованные цены»**, если в окне выбран файл или папка согласования цен (см. ниже).
- **Сверяет с листом «link»** по «ВспР»: ставит «есть»/«нет» в колонку «Линк», сравнивает
  даты и грейды, и пишет результат в «Проверка запретов» (см. ниже).
- **Проверяет протянутые колонки** — стенки, аналоги, согласованные цены.
- **Смотрит «МП»**: если он равен количеству поставки, возможно, это поставка МП. Проверить это
  можно только в слежении или в «Отчёте по заказам» МЦ, поэтому формулу «Кол-во за вычетом мп
  и блогеров» программа не меняет — ячейка подсвечивается, а в замечании написано, что делать.

### «Проверка запретов»

В «link» по строке на каждый магазин. Грейд магазина — колонка «Группа_ам» (A, B, C1, …,
O120, O140), а положен ли ему АЦР — «Вкл» = 1 и обе «Deny goods» = 0. Так программа
и считает — по каждому грейду: сколько в нём магазинов и скольким АЦР положен. Колонка
«Группы_ок» одинакова во всех строках и о запретах ничего не говорит, поэтому не используется.

- **«Ок»** — «Вкл» везде 1, «Deny goods» везде 0, даты «link» совпали с «Периодом продаж
  магазины», грейды сходятся. Исключение — грейды, которые в «Цены» не отмечены: если АЦР
  не идёт на острова («Период продаж острова», O120 и O140 = 0), в «link» у островов «Вкл» = 0
  или «Deny goods» = 1 — так и должно быть, и это тоже «Ок».
- **«Запрет на грейдах F, G…»** — во всех магазинах этих грейдов АЦР запрещён, а в «Цены»
  грейды отмечены 1. Это замечание, а колонки грейдов подсвечиваются. Если колонки грейда
  на листе нет, о его запрете замечание пишется всегда.
- **«Запрет в части магазинов: E - 4 из 5…»** — запрещено не во всех магазинах грейда.
  Пишется в колонку, но в замечания не выносится: такие запреты бывают почти у каждого АЦР.
- **«В «link» положены, но в «Цены» не отмечены: …»** и **«Отмечены в «Цены», но в «link»
  магазинов этих грейдов нет: …»** — расхождение грейдов.
- Сверяются и грейды островов O120 и O140, если их колонки есть на листе. Буква «О»
  в «link» и в заголовке бывает и латинской, и кириллической — это один грейд. Раньше
  программа этих колонок не видела и писала «разрешены, но не отмечены: O120, O140»
  при всём включённом в «link».
- **Острова без грейда.** В одних книгах у островов в «Группа_ам» стоит O120 / O140, в других
  (пример распреда) «Группа_ам» пустая, а в «Концепт» — «ОСТРОВ». Такие строки считаются
  одной группой «острова без «Группа_ам»» — это O120 и O140 вместе: островам АЦР положен,
  если в «Цены» отмечен хотя бы один из них. Если оба = 0, запрет островов в «link» — «Ок».
- Пустой «Вкл» ничего не запрещает: запрет в «link» всегда записан явно.
- Даты берутся из строк магазинов; строки островов идут в расчёт, только если у магазинов дат нет.

### Согласованные цены

В инструкции это шаг, про который сказано «подумай, как лучше»: ВПР на файл из папки КМ
«Согласование цен» → папка сезона, найденный по номеру поставки. Теперь так:

- На странице «Распред · пересчёт» есть поле **«Согласование цен: файл или папка»**. Выбор
  запоминается. Можно выбрать **файл** — в окне выбора папки файлов не видно, и нужный файл
  там не найти: тогда цены сначала берутся из него, а недостающие ищутся в его папке. Можно
  выбрать **папку** — подойдёт папка сезона или вся «Согласование цен» у КМ, подпапки
  просматриваются на три уровня вглубь. Ничего не выбрано — колонка берётся такой, как протянута.
- Для каждой поставки из колонки «Поставка» ищется файл, в названии которого есть её номер.
  Буква в номере может быть набрана латиницей или кириллицей — «C2518-084» и «С2518-084»
  одно и то же. Если файлов несколько, первым берётся самый новый.
- В файле ищется таблица с колонками «ШК» и «Розничная цена», а если такой нет —
  «Предложение УТЗ». Цена по штрихкоду пишется в «Согласованные цены» **значением**:
  формула со ссылкой на закрытый файл на сетевом диске теряет цифры, когда папка недоступна.
- Если файла поставки нет или в нём нашлись не все штрихкоды, программа берёт ближайшие
  файлы «по первым цифрам поставки»: у «431-329» это «431-328», «431-330» и дальше,
  до десяти файлов. Какие цены взяты оттуда, написано в замечаниях — их стоит проверить.
- Не нашлось нигде — замечание со списком штрихкодов, ячейки остаются как были.
- Файлы открываются только для чтения, без обновления связей и с отключёнными макросами,
  и закрываются без сохранения. Файл с паролем не открывается — это тоже замечание в журнале.

Проверено на примере: файл «431-329» с двумя штрихкодами из трёх и соседний «431-330» —
две цены из файла поставки, третья из ближайшего, файл «318-329» другой поставки не тронут.

### Жёлтые листы

**Программа листы не удаляет.** По инструкции после проверки удаляются жёлтые листы —
«link», «Сводный прайс», «Прайс по подразделениям», «Остатки Н», «Аналоги», «Регламент
наценок», «КС». В версиях 1.18–1.19.3 пересчёт делал это сам, но в готовом файле листы
нужны: удаляет их аналитик, когда сочтёт нужным. Все книги, которые выдаёт программа,
остаются со всеми листами.

### Что подсвечивается

Пометка ставится на ту ячейку, к которой относится, и снимается при следующем запуске —
но снимается только своя заливка, цвет аналитика сохраняется.

- штрихкод не найден в «Сводном прайсе»;
- штрихкод в инвойсе повторяется — в «цена_закупочная» записана сумма повторок, а сами
  одинаковые штрихкоды в «Копия ШК» выделены цветом своей группы;
- «МП» равен количеству поставки;
- наценка не проставлена: сектора нет в регламенте либо выбор не сделан;
- «Период продаж магазины» пуст, равен нулю или не подтянулся из стенок;
- даты в «link» и в «Цены» не совпадают;
- грейд, у которого АЦР в «link» запрещён во всех магазинах, отмечен в «Цены»;
- грейд отмечен в «Цены», а магазинов этого грейда в «link» нет;
- «Аналог стенки» и «Аналог гугл» противоречат друг другу;
- «Проверка цен» даёт ЛОЖЬ или не считается;
- АЦР нет в «Линке».

### Лист «остатки»

Это транспонированная выгрузка «Остатки Н», отобранная по сектору поставки: строка листа —
колонка выгрузки, колонка листа — один АЦР. Программа перезаполняет его целиком:

- **саму выгрузку не трогает.** «АЦР» собирается из артикула, цвета и размера в памяти,
  лишние колонки («АЦ», «Резерв», «Без маркировки», «Остаток маркетплейс»,
  «Остаток нет маркировки») в памяти же отбрасываются. Лист остаётся тем, что выгрузили,
  и повторный запуск не зависит от того, правили его руками или нет;
- в первую ячейку пишется сегодняшняя дата;
- рядом со строками «001 тз» и «001 в_пути» ставится код магазина (`=ЛЕВСИМВ(B37;3)`) —
  по нему «Распред» собирает остаток магазина. У строк «001 прод» кода нет: проданное
  остатком не является.

Из 17 тысяч строк выгрузки читаются только строки нужного сектора. Программа сначала
читает одну колонку «Сектор», а потом забирает найденные строки непрерывными кусками:
выгрузка обычно отсортирована по сектору, и тогда чтение выходит одно.

### Лист «Распред»

Лист почти целиком состоит из формул, и формулы блока АЦР сами подстраиваются под номер
своей колонки (`ИНДЕКС(Цены!$D:$D; 2+(СТОЛБЕЦ()-СТОЛБЕЦ($N$18))/4)`). Поэтому новый блок —
это копия первого, а не набор новых формул.

1. **Число блоков доводится до числа кодов.** Колонки вставляются и удаляются внутри
   занятого блоками диапазона: тогда Excel сам растягивает формулы, которые охватывают все
   блоки сразу — «Итого» строки РТТ и суммы по строкам «Заказ», «Ед», «МП».
2. **Ссылки на «остатки» переводятся на его фактические размеры.** Это отдельный шаг
   инструкции: Excel не растягивает ссылки на другой лист сам. У диапазона, растянутого
   по колонкам, меняется последняя колонка; у растянутого по строкам — последняя строка.
3. **Первый блок размножается** на остальные. Заодно в заголовок каждого блока встаёт
   фотография его АЦР — та, что лежит на листе «Цены» в строке этого товара. Своей картинки
   у блока само собой не появляется: копирование размножило бы картинку образца по всем
   блокам, поэтому старые картинки из области блоков сначала удаляются.
4. **Сектор** пишется в свою ячейку — по нему таблица РТТ подтягивает из «типы по секторам»
   климат, дивизион, город, тип и рейтинг каждого магазина.
5. **Подгруппы и доли сезонности.** Подгруппы берутся из «Цены» без повторов и по алфавиту.
   Доля месяца — сумма недельных долей с листа «КС». Недели считаются по производственному
   календарю: первая неделя года — та, на которую приходится 1 января, и неделя идёт
   в расчёт месяца, если в этом месяце лежат хотя бы три её дня. По такому счёту в 2026 году
   52 недели — ровно столько колонок и на листе «КС», — а декабрь заканчивается неделей
   28 декабря, у которой номер уже первый. Строка «КС» ищется по паре «Группа + Подгруппа»:
   одна и та же подгруппа встречается в разных группах.
   Трём секторам доли после этого **пересчитываются по шаблону**: доля месяца делится
   на сумму долей за месяцы, которые идут в расчёт, — 4 % и 6 % превращаются в 40 % и 60 %.
   У «БИЖУТЕРИЯ» таких месяцев два, у «КОЛГОТКИ,НОСКИ» и «УКРАШЕНИЯ ДЛЯ ВОЛОС» — три.
   Третий месяц бижутерии остаётся таким, как посчитался с «КС»: он справочный.
   Остальным секторам пересчёт не делают.
   **«Мин раздача»** — её вносит человек по подгруппе. Список подгрупп пишется заново,
   и значения прошлого распреда стояли бы напротив чужих подгрупп или пустых строк под
   списком. Поэтому значение остаётся только у подгруппы, у которой оно уже было, а все
   прошлые значения из блока убираются.
6. **«Мин запас на Хаб» обнуляется** там, где доля остатка вышла меньше 30 %: хаб придержит
   меньше, в загрузку уйдёт меньше, и остаток подрастёт.
7. **Таблица РТТ сортируется по «рейтингу».**

Месяцы программа не спрашивает: берёт три подряд, начиная со следующего за текущим —
распред делают на месяцы вперёд, а текущий уже наполовину прошёл. Какие месяцы взяты,
она пишет в замечаниях. В расчёт распределения идёт доля **первого** месяца, остальные
два справочные.

### Лист «Загрузочник»

Лист сам считает всё, что ему нужно, формулами. Программе остаётся привести его к размеру
поставки:

1. **Число колонок доводится до числа кодов.** Как и на «Распреде», колонки вставляются
   и удаляются внутри уже занятого диапазона — тогда «Итого» строк РТТ и суммы над таблицей
   растягиваются сами. Формулы `СУММПРОИЗВ` смотрят на «Распред», и его колонки к этому
   моменту уже переставлены: такие ссылки Excel растягивает сам.
2. **Первая колонка размножается** на остальные — её формулы ссылаются на собственную
   ячейку кода и в копии начинают считать свой код.
3. **Коды листа «Цены» вписываются в строку заголовков** — это и есть «скопировать колонку
   «Код» и вставить транспонированием».
4. **Проверка читается последней.** Ячейка со сравнением должна дать «ИСТИНА»; читается она
   после того, как посчитаны и распред, и обнулённый «мин запас на Хаб». Если вышло «ЛОЖЬ»
   или ошибка формулы — появляется замечание, и по нему можно перейти прямо в эту ячейку.

Ни буквы колонок, ни номера строк не зашиты: строка заголовков находится по паре подписей
«Код» … «Итого», а ячейка проверки — по виду формулы (единственное сравнение над таблицей),
потому что подписи у неё нет.

Отдельно обрабатывается случай, когда в заготовке осталась **одна** колонка кода — так бывает
после поставки с единственным кодом, чей загрузочник становится заготовкой для следующей.
Диапазон из одной ячейки Excel расширить не может: `СУММ(G13:G13)` при вставке не растягивается,
а уезжает. Поэтому колонки в этом случае вставляются справа от единственной, а суммы по колонкам
кодов чинятся явно — одноячеечный диапазон внутри полосы кодов растягивается на всю полосу.
Сумма по колонке (`СУММ(G13:G131)`, разные строки) под правило не подходит и остаётся как есть.

### Чего программа не делает

**Стенки не открывает.** Колонки со стенками (`\\FileServer\склад$\…`) протягивает аналитик —
программа их только читает, сверяет и подсвечивает. Из сетевой папки программа читает одно:
файлы согласования цен, и только когда папку выбрал человек. Чужие файлы остаются нетронутыми.

При этом сетевая папка со стенками должна быть доступна **в момент запуска**. Формулы
в этих колонках ссылаются на закрытый файл на сетевом диске, и при вставке строк Excel
пересчитывает их заново: без доступа к папке он теряет сохранённые значения и ставит
«#ССЫЛКА!». Программа это замечает и пишет отдельное замечание — его легко отличить
от «позиции нет в стенках».

Остаётся ручным: согласование дат с КМ («к дате как в стенках или как приедут»), проверка
в слежении, не поставка ли это МП, и переписка с баерами, когда артикула нет в стенках.
Между двумя этапами распреда — протягивание колонок со стенками: ради него этапы и разделены.

## Подтоварка МП

Отдельный отчёт: письмо «Подтоварка ‹МП›» приходит с книгой, аналитик подтягивает в неё
из сезонного файла «Запрет», «Фактическое кол-во, которое можно собрать на ВБ+Озон»
и «Прогнозный sellout» и обновляет листы «по адресам и таре», «Р» и «МПП». Дальше программа
за один запуск проходит инструкцию целиком: «Заметка» и лист согласования, места хранения,
«Не собрано», «Отдельно», листы «из‹место›» и загрузочники. Если листов мест хранения
в книге нет, она делает первую часть и пишет об этом в замечаниях — книга проверяется
на это сразу после выбора файла.

**Рабочие колонки программа дописывает сама.** Если на листе «на загрузку» нет «Заметок»,
«Проверки», «Места хранения», «1МП», «4А», «3В», «2МПП», «5СЗП» или «Р», они добавляются
справа от последней колонки книги в этом же порядке и в оформлении соседнего заголовка.
Готовить книгу заранее не нужно: хватает колонок аналитика. «Проверка» остаётся пустой —
что в ней считать, решает аналитик, и свою формулу программа не трогает.

**Колонка «в подтоварку»** бывает подписана городом: «в подтоварку Мск», «в подтоварку МСК»
или с другим окончанием — годится любой заголовок, который начинается со слов «в подтоварку».
Слова в середине заголовка («урезать в подтоварку») не считаются.

**Несколько городов.** Если колонок с количеством несколько — «в подтоварку Мск» и «… Спб»
либо «Склад Мск», «Склад Спб», «Склад Екб», — рядом должна быть итоговая: «Итого в подтоварку»
или «Итого на МП». Все расчёты идут по итогу: «Заметка», «Место хранения» и остатки мест —
одни на строку. По городам делятся только листы «из‹место›» и загрузочники: город берёт своё
количество по очереди, а следующему достаётся то, что осталось, — предыдущий город для него
всё равно что резерв. Если итоговой колонки нет, программа останавливается и называет
городские колонки: молча взять одну из них нельзя.

### «Заметка»

На листе «на загрузку» для каждой строки заполняется «Заметка»: можем отгрузить — «Ок»,
не можем — «Согласовать». Решает колонка «Запрет»:

| «Запрет» | Что делает программа |
|---|---|
| «доп согл» в любом соседстве («доп согл», «запрет, доп согл») | Везём только после отдельного разговора — «Согласовать». Ищется раньше остальных значений: что бы ни стояло рядом, разговор нужен |
| что угодно, но строка есть на листе «Исключения» | «Ок»: такой товар отдаём по остаткам мест хранения, не глядя на «Запрет» |
| «Отгрузка в рамках заказа МП, запрет забора из розницы» | Из розницы не берём, поэтому больше собираемого не увезём: «в подтоварку» урезается до «Фактического кол-ва», строка подсвечивается, «Заметка» — «Ок» |
| «Запрет забора из розницы» | Забирать нельзя ничего: строка подсвечивается, «Заметка» — «Согласовать» |
| «#Н/Д» | АЦР нет в сезонном файле, ограничений нет — «Ок» |
| пусто | См. ниже |

**Лист «Исключения»** ведёт аналитик: секторы, группы, артикулы и АЦР, которые отдаём
без согласования. Программа читает всё, что на нём написано, в любых колонках; АЦР сверяется
ещё и началом, так что «1235-190ЗОЛОТО» закрывает все размеры этого цвета. Листа в книге
нет — значит, исключений нет вовсе: раньше три сектора были зашиты в программу, теперь их
решает лист.

При пустом «Запрете» разница «Фактическое кол-во» минус «в подтоварку» считается только
там, где «Фактическое кол-во» заполнено и больше нуля: в ручной работе лист сначала
фильтруется по непустым значениям этой колонки, и формула пишется только в отфильтрованные
строки. Ноль и больше — хватает, «Ок»; меньше нуля — «Согласовать». Где собирать на ВБ+Озон
нечего, сравнивать не с чем — строка «Ок».

Всё, что попало в «Согласовать», собирается на лист **«Согласовать»** — он называется так
же, как в готовых подтоварках аналитика. На нём та же строка плюс колонка «Почему
на согласование» — с числами, а не общими словами («не хватает 5 шт.: можно собрать 20,
просят 25»). Лист пересоздаётся при каждом запуске.

Названия колонок в книгах разных маркетплейсов различаются: «Запрет» может называться
«Комментарий (на запрет)», «Заметка» — «Заметки». Программа понимает оба варианта.

Где данных не хватает — например, «Запрет» пуст и «в подтоварку» тоже, — программа
не угадывает: «Заметка» остаётся пустой, а строка попадает в замечания, по которым можно
перейти прямо в ячейку.

Где данных нет совсем — например, в «в подтоварку» стоит «#ССЫЛКА!», — количеством это
не считается: «Заметка» остаётся пустой, а строка попадает в замечания.

Колонка «в подтоварку» не перекрашивается: она закрашена аналитиком, и по цвету колонок
потом собирают листы «из‹место хранения›». Снятие пометки стёрло бы этот цвет.

### Листы мест хранения

| Лист | Откуда |
|---|---|
| «МП» | «по адресам и таре», тип хранения «Маркетплейс» |
| «А» | «по адресам и таре», «Хранение» и «Хранилище» |
| «В» | «по адресам и таре», «Возвраты», «Времянка» и «Олды» (в выгрузке — «ОЛД») |
| «СЗП» | «МПП», поставки на «С»: они переезжают на «СЗП» и с «МПП» удаляются |

В первой колонке «по адресам и таре», «Р» и «МПП» ставится АЦР формулой «Артикул & Цвет & Размер»;
если колонки «АЦР» нет, она вставляется первой. На «Р» остаются заказы текущего года, прошлые
годы удаляются. Листы «МП», «А», «В» пересоздаются при каждом запуске. «СЗП» — только когда
на «МПП» есть поставки на «С»: при повторном разборе той же книги их там уже нет, и остатки
берутся с готового «СЗП».

На «на загрузку» появляются колонки «Место хранения», «1МП», «2МПП», «3В», «4А», «5СЗП», «Р»:
остатки мест по АЦР — формулами СУММЕСЛИМН, как в инструкции (у поставок — «Отклонение»).
Цифра в названии — очередь, в которой место берётся. Колонку, названную по прошлой очереди
(«3А» вместо «4А»), программа переподписывает: цифра врать не должна. Колонки без цифр —
«МП», «А» — аналитик подписал сам, их программа только заполняет.

### «Место хранения»

1. **Одно место на всё.** Остаток места минус все резервы АЦР минус «в подтоварку» не меньше
   нуля — берём отсюда. Места перебираются в очереди **МП, МПП, В, А, СЗП**. В ячейке — просто
   название места: «МПП».
2. **Несколько мест.** Если одного места не хватает, количество набирается по той же очереди.
   Резервы теперь вычитаются с того места, где лежат, — это видно по комментарию заказа
   на листе «Р»: место, названное в нём первым («из адресов МП, А1,А2,А3, Возвратов» — МП).
   «Заказ интернет магазина» грузится с хранения — это «А», номер поставки «М…»/«Л…» — «МПП»,
   «С…» — «СЗП». Резерв «на образцы» и «на фото» берут с поставок — он снимается с «МПП»,
   а не хватит — с «СЗП»; «Опт» снимается с любого места, где есть остаток. Собралось —
   «МП10, А5» **красным текстом**.
3. **Не хватило** — в ячейке то, что есть: «А2», «МПП2, СЗП3» или «0», и **ячейка красная**.
   Такие строки собираются на лист **«Не собрано»** с колонками «Не собрано» и «Собрано».

Если по комментарию резерва место не понять («Пакеты сентябрь»), резерв ни из чего
не вычитается, а в замечании написано проверить комментарий в резервах.

### «Отдельно», листы «из‹место›» и загрузочники

- **«Отдельно»** — строки, в «коменте» которых есть «отдельн» («ОЧКИ - отдельный заказ»).
- **«измп», «измпп», «иза», «изсзп», «изв»** — по строке на каждое место, упомянутое
  в «Месте хранения»; «в подтоварку» — количество этого места («МП10» — 10). Код берётся
  с листа места хранения. Если на первом коде АЦР столько нет, берётся код, на котором хватает
  (из «3, 1 и 30» — тот, где 30), и строка **голубая**; если хватает только на нескольких кодах
  вместе, строка размножается по кодам, и эти строки **зелёные**. «Количество на этом коде»
  и «Остаток за вычетом количеств в загрузку» — формулами; у поставок есть ещё «Поставка»,
  а когда городов несколько — «Город» и строка на каждый. Остаток всё равно ушёл в минус —
  замечание с переходом прямо в ячейку.
- **Загрузочники** — отдельный лист на каждое место и каждый «комент»: «Очки отдельно»
  на «иза» и на «измп» — два загрузочника. Лист называется «З‹место›-‹начало комента›»:
  «ЗМП-любой», «ЗА-мелкий», «ЗМПП-352». У подразделения 206 склад не делит заказы по местам,
  и загрузочник собирается на каждый «комент» целиком: «З-микс», «З-крупное».
  Колонки — «Код», «Подразделение» (код клиента), «Количество», «Цена» («Цена на МП», если она
  есть, иначе «РЦ»), «Комментарий», «Номер заказа» и «Согласование». Комментарий: маркетплейс,
  город, «комент» и приоритет, а у поставок ещё их номера без повторов — «Ozon Мск Подтоварка
  Микс Приоритет к 28.09», «Lamoda Подтоварка Любой из М369-069, Л369-063 Приоритет
  к 07.09.2026». Номер заказа — номер города (Мск — 1, Спб — 2); у «моно» заказов каждый код
  грузится своим номером: 1, 2, 3.

**Строки, которые ждут согласования, из загрузочников не выкидываются.** Они попадают
и на листы «из‹место›», и в загрузочники, но выделены **жёлтым**, а в загрузочнике рядом
написано «На согласовании». Так заказ виден целиком, а что из него пока нельзя грузить —
видно с первого взгляда.

Остаётся за человеком — и по каждому загрузочнику есть замечание: можно ли столько передать
на склад, не объединить ли маленький заказ с другим, как поправить текст комментария.
Отдельное замечание говорит, сколько строк с «Согласовать» попало в загрузочники: их грузят
после согласования. Импорт в «Распределительный логист» и ответ на письмо — тоже вручную.

Загрузочник тапочек от 02.09 совпал с тем, что аналитик загрузила руками, строка в строку:
коды, количества, цены и номера поставок; отличается только текст комментария («Обувь»
вместо «Тапочки»).

## Приемка на хранилище

Отдельный отчёт по инструкции «Приемка на хранилище». Идёт двумя этапами, как распред:
между ними аналитик по каждому сектору решает, что написать в «Допоставить». Остатки,
продажи, прогноз и даты стенок программа за человека не взвешивает.

В боковой панели это два пункта — **«Приемка на хранилище · подготовка»** и **«Приемка
на хранилище · адреса»**. Название полное: просто «Приемка» — другой отчёт, и спутать
их нельзя. Длинное название переносится на вторую строку, а не
обрезается многоточием.

Перед запуском в книгу, как и раньше, вставляются свежие «План склада», «Удалили из плана
склада», «Непринятый товар в получ постав», «Согласование количества», «Склад»,
«Т.Остатки», «Остатки», «Резервы» и «Приходы». «Согласования количества» может не быть —
тогда программа просто скажет об этом.

**Рабочие колонки программа создаёт сама.** На листах «А2, А3» и «МП» это «Адрес», «Тара»,
«Артикул», «Код», «Сектор», «Группа», «Подгруппа», «наименование», «Качество», «Количество»,
«Размер», «Сезон», «Тема» и «Цвет»; на листах «Поставки собраны», «Поставки не собраны»
и «Поставки МП» - все колонки «Непринятого товара», от «Даты документа» до «Отклонения».
Если колонки нет, она встаёт на своё место по порядку, а не приписывается справа; если
колонка на листе есть, но без названия, программа её подписывает. Готовить эти листы
заранее не нужно - достаточно колонок с формулами: «В приемку», «Учитывать», «Номер адреса»
и «Номер тары» на листах адресов, «Код» и «Тара/код поставщика» на листах поставок.
Эти формулы программа не сочиняет; если они ссылаются на удалённые колонки, она пишет
об этом замечание.

### Подготовка

1. На всех листах снимаются фильтры.
2. **«Т.Остатки»** — удаляется брак: буква «Б» в коде. Если формула «Код» не дотянута
   до новых строк выгрузки, код берётся из последних шести знаков артикула — так же, как
   в самой формуле, — и об этом пишется замечание.
3. **«Остатки»** — удаляются строки «Denny goods» = «все» и все колонки, кроме одиннадцати:
   от «Сектор» до «Цвет», «Остаток хранилище» и «Продано итого». «Остаток хранилище»
   пересчитывается по «Т.Остаткам» и пишется значениями — то, что вручную делают
   СУММЕСЛИМН и «вставить как значения».
4. **«Резервы»** — удаляются резервы прошлых лет и всё, что не «РезервОтгрузка».
5. **«А2, А3» и «МП»** — со «Склада» берутся строки с типом хранения «Хранение»
   и «Маркетплейс». Колонки до «Цвет» заполняются **по названиям**: на «Складе» между
   «Количеством» и «Размером» стоит «Бренд», и вставка подряд сдвигает данные на колонку.
   Повторы тары убираются — остаётся первая строка, как у «Удалить дубликаты», — строки
   сортируются по коду и количеству, формулы первой строки протягиваются на все строки.
   Если в «В приемку» формулы нет, программа вписывает её сама — см. ниже.
6. **«Приходы»** — удаляется всё, что не «Запущено», разница до 9 единиц включительно
   и поставки на «Л». Остальное красится: «М» — розовым (маркетплейс), «С» из «Удалили
   из плана склада» — зелёным (собрана), «С» из «Плана склада» — голубым (не собрана).
   План проверяется вторым и перекрашивает, как при ручном разборе. Номера в этих листах
   часто сокращены — «2445-011,014,015», «327-037,38», — программа их разворачивает.
   Поставка, которой нет ни там, ни там, остаётся без цвета и попадает в замечания.
7. **«Поставки собраны», «Поставки не собраны», «Поставки МП»** — заполняются строками
   «Непринятого товара» по номерам поставок своего цвета; формулы «Код» и «Тара/код
   поставщика» протягиваются.
8. **«итог»** — в O1 пишется текущая неделя. Из «Остатков» остаются строки, по коду которых
   есть хоть что-то в «А2, А3», «МП» или в одной из трёх поставок — вручную это фильтр
   «ноль и меньше» по пяти колонкам и удаление. Формулы первой строки протягиваются;
   «Допоставить», место хранения, тара и штрихкод очищаются; «Количество МП» получает
   «Ответ МП» из «Согласования количества» там, где он больше нуля.

Повторный запуск подготовки собирает «итог» заново, и заполненное «Допоставить» при этом
пропадает.

### Адреса

Когда «Допоставить» решено:

1. Фильтры снимаются: «итог» обычно остаётся отфильтрованным по сектору, а под фильтром
   Excel не видит скрытых строк. Если в «В приемку» пусто — так бывает в файлах,
   подготовленных версией 1.17.0, — формула вписывается и протягивается здесь же:
   подготовку повторять не нужно, решённое «Допоставить» сохраняется.
2. Из строк «А2, А3», у которых «Учитывать» больше нуля, собираются **«адреса»** и **«тары»**:
   в первой строке каждого кода — все его адреса или тары через запятую, в остальных
   пусто. На «адресах» повтор адреса у одного кода убирается.
3. На «итоге» для строк с «Количеством» больше нуля «Место хранения» и «Тара/код
   поставщика» — ВПР с «адресов» и «тар». Для строк, где «Допоставить» заполнено
   и «Поставки собраны» больше нуля, — ВПР из «Поставок собраны»: номер поставки, тара
   и штрихкод.
4. Пустое «Допоставить» получает «Количество МП».
5. После пересчёта так же из «МП» собираются «адреса МП» и «тары МП».

### Формула «В приемку»

Выбор адресов держится на формуле «В приемку» листов «А2, А3» и «МП» — сколько по коду
строки решено допоставить:

```
=СУММЕСЛИ(итог!G:G;D2;итог!S:S)
```

«Учитывать» набирает количество с меньших тар, пока не покроет это число. В присланном
шаблоне формулы не было: при прошлой вставке со «Склада» данные съехали на колонку,
и в «В приемку» лежал цвет. Формулу подтвердила аналитик, и теперь программа, не найдя
её в первой строке, вписывает её сама — и на подготовке, и на этапе адресов — и пишет
об этом замечание. Буквы колонок берутся из заголовков «итога» и листа. Если в первой
строке уже стоит какая-то формула, она сохраняется и протягивается как есть.

### Что остаётся за человеком

- «Допоставить» по секторам — шаги 57–69 инструкции.
- Поставки на «С», которых нет ни в «Удалили из плана склада», ни в «Плане склада»:
  программа оставляет их без цвета, аналитик красит их сама.
- Проверка пересечений с прошлым файлом приемки — в инструкции это задача на будущее.

### Сверка с шаблоном

Подготовка прогнана по шаблону аналитика, результат сверен с ним колонка в колонку.
«Остатки» — 10 318 строк без расхождений, включая пересчитанный «Остаток хранилище».
«А2, А3» — 160 строк и «МП» — 2436, в том же порядке. На «итоге» 931 строка против 936:
не хватает пяти кодов из поставок С2446-004 и С2446-005. Их номеров нет ни в одном
из листов — аналитик покрасил их сам, — поэтому программа оставляет их без цвета
и называет в замечаниях. «Приходы», листы поставок и суммы «итога» по хранению,
поставкам и резервам отличаются только ими же.

## Обновления

Вкладка «Обновления» смотрит выпуски открытого репозитория на GitHub. Ни ключей, ни входа
в учётную запись не нужно — запрос обычный анонимный.

Порядок такой: при каждом запуске программа спрашивает GitHub, нет ли версии новее; если
есть — сразу скачивает её в фоне и оставляет одну кнопку **«Установить и перезапустить»**.
Пока идёт загрузка, с книгами можно работать как обычно; в боковой панели у «Обновлений»
появляется метка «новое», так что новость видна и с другой страницы.

Перезапуск не делается сам собой намеренно: в этот момент может идти обработка книги.
Если она идёт, установка откладывается до её окончания.

Сама подмена файла устроена так: программа не может переписать себя, пока работает, поэтому
она запускает маленький сценарий `cmd`, который ждёт закрытия окна, ставит новый файл на место
старого и запускает его. Если в имени текущего файла стоит его версия
(`WarehousePlanAutomation-1.8.0-win-x64.exe`), новый файл получает своё имя и кладётся рядом,
а прежний удаляется — иначе имя врало бы о версии. В остальных случаях файл заменяется на месте:
путь мог попасть в ярлык.

Черновики и предварительные выпуски не предлагаются. Выпуск без готового `.exe` тоже:
ставить было бы нечего.

**Проверка подлинности.** Рядом с `.exe` в выпуске лежит файл подписи `‹имя .exe›.sig`
(ECDSA P-256). Подписываются содержимое файла и его имя с версией — старый настоящий файл
нельзя выдать за новую версию. Закрытый ключ хранится только на компьютере разработчика,
в хранилище ключей Windows, и в GitHub не попадает; в программу встроен открытый ключ.
Программа скачивает подпись раньше файла и ставит обновление, только если подпись сходится.
Проверка повторяется прямо перед установкой. Выпуск без подписи или с неверной подписью
не ставится: файл удаляется, а во вкладке пишется, что обновление не прошло проверку.
Так даже доступа к репозиторию или аккаунту GitHub мало, чтобы подсунуть программе свой файл.

## Большие файлы

Обработка рассчитана на выгрузки в десятки и сотни тысяч строк:

- перед чтением снимается наложенный отбор автофильтра. Это обязательно с двух сторон: при
  активном отборе поиск последней заполненной строки останавливается на последней **видимой**,
  а `Range.Delete` удаляет строки только в видимой части диапазона. Кнопки автофильтра остаются;
- определяется фактическая последняя заполненная строка, а не формальный использованный диапазон,
  который в реальных файлах часто раздут далеко за пределы данных;
- из листа читаются только те колонки, которые нужны правилам;
- лист читается порциями по 50 000 строк, каждая порция сразу превращается в компактные объекты,
  поэтому книга целиком в памяти не держится;
- вся классификация выполняется в памяти, в Excel возвращаются только итоговые изменения;
- удаляемые строки объединяются в непрерывные блоки, а блоки — в пачки: за один вызов удаляется
  столько областей, сколько помещается в адрес диапазона. На выгрузке в 150 000 строк это вдвое
  быстрее построчного удаления (9 с против 18 с в замере).

## Журнал работы программы

Технический лог пишется в:

```
%LOCALAPPDATA%\WarehousePlanAutomation\Logs\warehouse-plan-ГГГГ-ММ-ДД.log
```

В нём фиксируются этапы обработки, имя файла, количества обработанных строк и полные тексты
ошибок. Если обработка сорвалась неожиданно, в окне кроме сообщения видна и причина — тип
и первая строка ошибки: журнал лежит на рабочем компьютере и к вечеру очищается, а строку
из окна легко переслать снимком экрана. Полный текст остаётся в логе.
Журнал лежит только на этом компьютере и никуда не отправляется.

**Журнал хранится до вечера.** Каждый день в 20:00 удаляется всё, что записано до этого времени.
Программа не служба и в 20:00 может быть закрыта, поэтому срок проверяется трижды: при запуске,
в 20:00, если программа открыта, и при её закрытии. Запись, сделанная после 20:00, живёт
до следующего вечера.

## Принятые уточнения к техническому заданию

Эти решения приняты по реальным данным из файла-примера и зафиксированы в коде и тестах:

- **Номер поставки.** Формат — необязательные буквы, цифры, дефис, цифры (`2412-015`, `МЗ352-133`).
  В каждой числовой части требуется не менее трёх цифр. Иначе номером поставки ошибочно
  считались бы обозначения сезона вида `FW26-27`, которые встречаются в комментариях.
- **«Магнит» ищется как отдельное слово**, а не как подстрока: иначе под правило маркетплейсов
  попал бы обычный магазин «Магнитогорск-М66». По той же причине как отдельные слова
  сопоставляются короткие «ВБ» и «WB». Для остальных названий используется вхождение подстроки,
  как задано в ТЗ.
- **Номер загрузки должен стоять сразу за словами «Номер загрузки»**: между ними допускаются
  только разделители, не больше пяти символов. Иначе в комментарии вида
  «Номер загрузки не указан, отгрузка 05.09» номером загрузки стало бы число 05.
- **Номер загрузки в журнале сопоставляется с границами по цифрам.** «44575395» не находится
  внутри «155575395» или «555753950», иначе заказу достался бы статус чужого заказа.
- **Статус «Запущен» ищется во всех вхождениях журнала, включая первое.** Строка «Запущен»
  с нулевым процентом означает, что заказ уже в сборке, независимо от её места в журнале.
- **Признак «перекр» определяется по тексту «Поставки»**, то есть по части комментария
  до слов «Номер загрузки». Номер поставки, случайно попавший в служебный хвост комментария,
  новой поставкой не считается. По тому же тексту сравниваются номера поставок
  при удалении строк «Заказы будут загружены».
- **Порядок строк программа не меняет.** План ведёт аналитик, и её расстановка — решение,
  а не побочный результат правил. Всё сегодняшнее собирается внизу блока: новая строка встаёт
  под последнюю строку своего блока, а не в середину. Колонка «№» после этого нумеруется заново,
  чтобы номера остались сплошными.
- **Новые строки между собой сортируются** по правилам аналитика: срочные («сроч» в «Поставках»)
  выше несрочных; дальше по дате в сети — «в рознице с 01.10» выше «в рознице с 08.10», строки
  без даты в тексте («отгрузка по готовности») первыми; при одной дате — сначала СЕТ (СЕТ1 выше
  СЕТ2), потом МОНО, потом остальное. «CET» и «MOHO», набранные латиницей, — те же слова;
  «в сети» признаком СЕТ не считается. Старые строки блока не переставляются.
- **Пометки цветом ставятся только на «Номер загрузки»** и снимаются при следующем запуске —
  но снимаются лишь свои два цвета, «Хорошо» и «Плохо». Если аналитик покрасила ячейку сама,
  её цвет сохраняется.
- **Признак «ЗП» ищется как отдельный признак**, а не как подстрока: «ЗП373-1739» находится,
  «зп» внутри другого слова — нет. Правило применяется после разбора подразделений:
  строки «Опт», «777» и маркетплейсов и без того удаляются, но их количества нужны в итогах
  блоков, и «ЗП» в комментарии не повод выкидывать их из этих сумм.
- **Формулы не заменяются значениями.** Если «Количество единиц», «статус» или «% выполнения»
  в строке заданы формулой, программа их не трогает. Уже проставленный статус «в сборке»
  не переписывается: в книге встречаются написания «в сборке» и «в сборке.», привычное
  пользователю сохраняется.
- **Названия маркетплейсов.** Кроме написаний из ТЗ распознаются латинские варианты
  (`Ozon`, `Lamoda`, `Wildberries`, `Sber`, `Magnit`), которыми выгрузка называет те же подразделения.
- **Листы ищутся по началу названия.** Точное совпадение сильнее: если лист назван ровно
  «План», берётся он, даже когда рядом лежит «Плановые остатки». Если под название подходят
  несколько листов и ни один не совпадает точно, программа не угадывает, а называет их
  в сообщении об ошибке. В книге распреда это правило принципиально: там есть и «прайс»,
  и «Прайс по подразделениям», и «остатки», и «Остатки Н» — разводит их только приоритет
  точного совпадения. Исключение — инвойс: его листов может быть несколько, по листу на поставку, и берутся все.
- **Единица измерения в названии колонки отбрасывается.** «цена, CN¥», «сумма, CNY»,
  «количество (шт.)» — это те же «цена», «сумма» и «количество»: хвост после запятой или
  скобки в расчёт не идёт. Через пробел хвост отбрасывается только если это обозначение
  валюты («цена CNY»), поэтому «цена продажи» колонкой «цена» не становится, а «% выполнения»
  не подменяет «%».
- **Заголовки таблицы инвойса ищутся глубже обычного** — до сороковой строки. Над ними стоит
  шапка с продавцом, покупателем, условиями поставки и портами: в разобранном инвойсе
  заголовки оказались в строке 23.
- **Штрихкод пишется числом, если он число.** В «Сводном прайсе» и в файлах согласования цен
  он тоже число, и текстовый штрихкод перестал бы с ними совпадать. Внутри программы он
  всегда сравнивается как строка цифр: через `double` длинный штрихкод превратился бы
  в «1,9E+09».
- **Формулы под таблицей «Цены» растягиваются на фактические строки.** Excel растягивает
  диапазон сам, только когда строки вставлены внутрь него, а они добавляются под последней —
  за границей. Без этого «=SUBTOTAL(9;P2:P2)» после добавления двух строк продолжал бы
  показывать одну. Диапазоны на других листах не трогаются.
- **Период продаж сравнивается по дню и месяцу.** В стенках он записан как «01/08-31/01»,
  без года; в «link» это настоящие даты. Придумывать год значило бы решать за книгу.
- **Грейды сверяются по грейду магазина «Группа_ам»** и «Вкл» / «Deny goods» его строк,
  как в инструкции. Грейд запрещён, если АЦР запрещён во всех его магазинах; запрет части
  магазинов пишется отдельно и запретом грейда не считается.
- **Неделя относится к месяцу своего четверга** — обычное правило нумерации недель.
  По нему октябрь 2026 года это недели 40–44, а ноябрь — 45–48, и доли, посчитанные так,
  совпали с теми, что стоят в разобранном файле (6,22 % и 6,46 % против записанных 6 % и 6 %).
- **Строки, которые Excel примет за число, пишутся в текстовом формате.** Значение,
  записанное в ячейку, Excel разбирает так же, как набранное руками, и запятые считает
  разделителями разрядов: перечень магазинов «150,155,156,158,…» из колонки «Denny goods»
  без этого превращается в 1,5E+113.
- **Число блоков «Распред» берётся задуманное, а не пересчитанное по листу.** Сразу после
  вставки колонок подписей «в загрузку» в них ещё нет, и пересчёт по листу дал бы старое
  число.
- **Код ошибки Excel не считается числом.** Ошибка приходит из COM большим отрицательным
  числом, и без проверки «#Н/Д» в доле остатка прошло бы как «меньше 30 %» и обнулило
  «мин запас на Хаб» ни за что.
- **Разметка «Распред» читается из его же формул.** Строки заголовков у листа нет: блок
  сезонности и ячейка сектора нигде не подписаны, но обе стоят в формулах таблицы РТТ.
  Читать адреса оттуда точнее, чем задавать их числом.
- **Заголовки колонок** ищутся по четырём проходам: полное совпадение, полное совпадение
  без единицы измерения, начало строки, вхождение.
  Это позволяет находить и «Дата в сети (без целевой даты, отгрузка и сборка 15 дн)», и «Разница ед».
  Колонка «%» журнала ищется только полным совпадением, чтобы не спутать её
  с «% оклейка», «% отгрузка», «% сборка».
- **Вставка и удаление строк «Плана» идут только внутри колонок таблицы.**
  Если двигать строку целиком, вместе с ней уезжает всё, что стоит справа: на листе есть
  боковая сводка «норма в день / просрочка / в план». Строка сводки, попавшая под удаление,
  пропала бы совсем. Побочный
  эффект такого способа — высота строк остаётся за их номерами, поэтому в конце обработки
  высоты расставляются заново по образцу: у строк-заголовков блоков, у «Приемки на хранилище»
  и «автозаказов для хабов», у обычных строк заказов и у подстрок «заказы МП» берётся
  та высота, которая была у них во вчерашнем файле.
- **«Дата документа» новой строки** берётся из сегодняшней выгрузки без времени: в «Плане»
  хранятся целые даты, и формула «Дней в работе» должна давать целое число дней.
- **Разделитель областей в адресе диапазона** берётся из настроек Excel
  (`Application.International`). На русской системе это «;», на английской — «,»,
  и жёстко задать его нельзя.
- **Итоговые формулы блоков.** После вставки и удаления строк диапазон формулы вида `=SUM(J5:J24)`
  восстанавливается с тем же отступом от начала блока, что был во вчерашнем файле
  (в блоке «все группы» сумма начинается после строк «Приемка на хранилище» и «автозаказы для хабов»).
- **COM-автоматизация — позднее связывание.** Программа обращается к `Excel.Application` через
  позднее связывание, без библиотек типов Microsoft Office. Это позволяет собирать проект
  на GitHub-раннере без установленного Office и работать с любой версией Excel у пользователя.
- **Публикация в один файл.** Требует свойства `BuiltInComInteropSupport`: в режиме одного файла
  встроенная поддержка COM по умолчанию отключается, и позднее связывание падает с ошибкой
  «`System.__ComObject` does not contain a definition for ...». Обрезка сборки (`PublishTrimmed`)
  недопустима по той же причине — позднее связывание не поддаётся статическому анализу.

### Оформление окна

Стили собраны в `App.xaml`, а цвета — отдельно, в `Themes/Light.xaml` и `Themes/Dark.xaml`
с одинаковыми ключами. Переключение темы — замена одного словаря на другой; работает это
только потому, что стили ссылаются на кисти через `DynamicResource`: `StaticResource`
запомнил бы цвет один раз, при разборе разметки. Адрес словаря пишется полным pack-путём
с именем сборки — относительный разрешается от запускающей сборки, и окно, собранное
из другого приложения (например, из харнесса снимков), его бы не нашло.

В светлой теме белые карточки на мягком тёплом поле, и боковая панель тоже тёмная: она
работает якорем — содержимое рядом с ней читается светлым листом, а сама она не спорит
с ним за внимание, потому что в ней нет ни чисел, ни данных. Акцент внутри панели свой,
светлее основного: индиго `#43479B` на тёмном почти не виден. В тёмной теме панель, наоборот,
темнее поля — светлая выглядела бы наклейкой, — а смысловые цвета взяты приглушённее:
насыщенный зелёный и оранжевый из светлой темы на тёмном выжигают глаза, а тёмно-красный
не читается. Выбор запоминается рядом с журналом работы, в `theme.txt`.

Стили заданы с ключами (`PrimaryButton`, `SecondaryButton`, `Card`, `PathTextBox`,
`SlimProgressBar`, `NavItem`), а не неявно по типу, иначе они протекали бы в системные диалоги.
Исключение одно — `ScrollBar`: стандартная в WPF рисуется широкой серой лентой со стрелками
и в спокойном окне выглядит чужой.

Шрифт системный, Segoe UI: окно должно выглядеть частью Windows, а не сайтом. Цифры счётчиков
идут табличными (`Typography.NumeralAlignment="Tabular"`) — иначе соседние плитки в ряду
выглядят разъехавшимися.

Окно — боковая панель со списком страниц и содержимое справа. Кнопки «Назад» нет намеренно:
список виден всегда, и переход — один щелчок из любого места. `MainWindow` держит только
оболочку, экран задачи живёт в `Views/WorkbookTaskView.xaml` и одинаков для всех задач;
отличаются они текстами и своим `IWorkbookProcessor`. Общее поведение — выбор файла,
перетаскивание, прогресс, отмена, счётчики, замечания — вынесено в `WorkbookTaskViewModel`,
наследники задают только тексты. Страница обновлений — тот же `NavPageViewModel`, но задачей
не является: книг она не открывает.

Цвет надписи в стиле сильнее унаследованного, поэтому неявный стиль `TextBlock` намеренно
**не** задаёт `Foreground`: надпись на кнопке рисует тот же `TextBlock`, и заданный там цвет
перебил бы белый цвет кнопки-акцента. Обычный текст получает цвет по наследству — `Foreground`
задан у окна и у экранов.

Заголовок окна рисует Windows, и сам он под тему не подстраивается. `TitleBarTheme` просит
об этом систему через `DwmSetWindowAttribute`: на Windows 11 цвет задаётся точно
(`DWMWA_CAPTION_COLOR`), на Windows 10 доступен только переключатель «тёмный заголовок».
Вызывается при запуске и при каждом переключении темы.

### Осмотр книги до запуска

Книга `.xlsx` — это zip, и список листов лежит в одном маленьком файле внутри
(`xl/workbook.xml`), а адреса связанных книг — в связях внешних ссылок. Прочитать их —
**23 мс даже на книге в 76 МБ**, тогда как открыть такую книгу в Excel это десятки секунд.
Поэтому `WorkbookProbeReader` смотрит книгу сразу после выбора файла, без Excel, а
`PreflightCheck` говорит, все ли нужные листы на месте и доступны ли связанные файлы —
до того, как человек нажмёт кнопку и будет ждать полминуты.

Заголовки колонок здесь не проверяются намеренно: для этого книгу пришлось бы открывать,
а это и есть та самая долгая часть.

### Разные экраны

Три меры, а не одна:

- **Размер окна берётся от рабочей области экрана** (`SystemParameters.WorkArea`), а не задаётся
  числом: на ноутбуке 1366×768 фиксированные 1180×760 не помещаются, на большом мониторе выглядят
  форточкой. Доля подобрана так, чтобы рядом оставалось место для окна Excel.
- **Ниже 1120 px боковая панель сворачивается в значки** — 64 px. Число не круглое, а посчитанное:
  при отступах пункта 10 и внутренних 12 значок шириной 20 встаёт ровно по центру. Ширину задаёт
  сама панель через `DataTrigger` на `IsCompact`, поэтому состояние одно и в коде окна ширина
  не дублируется. Значки при этом остаются: по ним задачу и узнают.
- **Ширина содержимого ограничена 1060 px.** На широком мониторе строка замечания через весь
  экран нечитаема, а карточки, растянутые на 2000 px, выглядят пустыми. Плитки счётчиков лежат
  в `WrapPanel` и переносятся на вторую строку сами: их число зависит от задачи, а ширина окна —
  от экрана.

Масштабирование по DPI обеспечивает манифест: `permonitorv2`. Без него на мониторе со
150-процентным масштабом окно рисовалось бы растянутой картинкой.

### Переход к замечанию

Замечание несёт не только текст, но и координаты: `ProcessingWarning.Sheet` и `.Cell`.
Названия листов берутся из книги, а не из схемы — в схеме записано только начало названия.
Проверки листа «Цены» считаются по строкам в памяти и адресов не знают, поэтому адреса им
проставляет слой Excel, где разметка листа уже прочитана.

Открывает книгу `WorkbookNavigator`. Главное там — не открыть вторую копию: если книга уже
открыта у аналитика, новый экземпляр Excel открыл бы её только для чтения, а несохранённые
правки остались бы в первом. Поэтому программа сначала присоединяется к работающему Excel
через таблицу запущенных объектов (`GetActiveObject`) и только потом запускает свой.

Перед выходом навигатор освобождает все обёртки COM, а приложение Excel — полностью
(`FinalRelease`). Без этого живая ссылка осталась бы в программе, и `EXCEL.EXE` продолжал бы
висеть в памяти уже после того, как аналитик закрыл окно книги.

Двойной щелчок по строке — это два нажатия кнопки, поэтому переход защёлкнут: второе нажатие
не запускает свой Excel, пока первый ещё не зарегистрировался и не находится.

Вопрос человеку посреди обработки идёт через `IDecisionPrompt`. Обработка выполняется
на своём STA-потоке, поэтому реализация в приложении переключается на поток интерфейса
через `Dispatcher.Invoke` и там показывает модальное окно. Блокировать поток обработки
безопасно: все вызовы COM исходящие, входящих обратных вызовов из Excel нет.

Иконка приложения рисуется кодом: `tools/IconGenerator` собирает `app.ico` из восьми кадров
(16…256 px) средствами WPF, без сторонних пакетов. Крупные размеры — лист документа
с акцентной шапкой, мелкие (32 px и меньше) — сплошной силуэт, иначе контур и белая заливка
сливаются. Проект намеренно не включён в решение, поэтому CI и релиз его не собирают.
Перерисовать иконку:

```bash
dotnet run --project tools/IconGenerator -- src/WarehousePlanAutomation.App/Assets/app.ico
```

`WarehousePlanAutomation.Core` не зависит ни от WPF, ни от Excel Interop: вся классификация
заказов, разбор журнала, нумерация, сборка строк «Цены» и все проверки выполняются
над массивами в памяти. Слой Excel только читает диапазоны, вставляет, копирует и удаляет
строки. Обе задачи реализуют один и тот же `IWorkbookProcessor` и делят поиск листов,
поиск заголовков, чтение больших листов порциями и пометку ячеек цветом.

### Сборка и релиз в GitHub Actions

Рабочий процесс: `push` кода → GitHub → Actions → готовый .exe.

- **CI** (`.github/workflows/ci.yml`) запускается на `push`, `pull_request` и вручную
  (`workflow_dispatch`): восстановление пакетов, сборка Release, прогон тестов.
- **Release** (`.github/workflows/release.yml`) запускается вручную либо по тегу вида `v*`.
  Он собирает `win-x64`, `Release`, `self-contained`, в один файл, проверяет, что публикация
  действительно вернула единственный .exe, и загружает его как артефакт сборки. При запуске
  по тегу дополнительно создаётся GitHub Release с прикреплённым .exe. Используется встроенный
  `GITHUB_TOKEN`, внешние сервисы не нужны.

Чтобы выпустить версию:

```bash
git tag v1.1.0
git push origin v1.1.0
```

Когда рабочий процесс Release создал выпуск, его нужно **подписать** на компьютере разработчика —
без подписи программа обновление не поставит:

```powershell
powershell -ExecutionPolicy Bypass -File tools/sign-release.ps1 -Tag v1.1.0
```

Сценарий скачивает `.exe` выпуска, подписывает его ключом из хранилища Windows
(`tools/ReleaseSigner`), проверяет подпись ключом, встроенным в программу, и прикладывает
`‹имя .exe›.sig` к выпуску. Ключ создаётся один раз командой
`dotnet run --project tools/ReleaseSigner -- keygen`; выгрузить его из хранилища нельзя.
Если ключ потерян (переустановка Windows, другой компьютер), создаётся новый, открытый ключ
в `UpdateSignature.PublicKey` меняется, и эту версию пользователи один раз скачивают вручную.
