Ты — senior Windows/.NET developer и DevOps engineer.



Нужно создать ПОЛНОСТЬЮ ГОТОВОЕ production Windows-приложение для автоматического формирования ежедневного Excel-плана склада.



Это не прототип.

После выполнения задачи репозиторий должен быть готов к push на GitHub, GitHub Actions должен собрать конечный Windows-дистрибутив, а пользователь должен иметь возможность скачать готовый artifact/release и работать.

==================================================

1\. ОБЯЗАТЕЛЬНЫЙ СТЕК

==================================================



Использовать:



\- C#

\- .NET 8

\- WPF

\- Windows x64

\- Microsoft Excel COM Automation / Microsoft.Office.Interop.Excel



Причина:

нужно максимально точно сохранять существующие:

\- Excel formulas;

\- formatting;

\- merged cells;

\- conditional formatting;

\- number formats;

\- Excel calculation behaviour.



НЕ использовать openpyxl как основной движок.



НЕ переписывать Excel-файл в собственную модель с последующей генерацией с нуля.



Приложение должно автоматизировать реальный установленный Microsoft Excel.



Runtime-требование:

на компьютере пользователя должен быть установлен Microsoft Excel.



Если Excel не установлен или COM недоступен:

показать понятную ошибку на русском и не изменять файл.

Интерфейс минимальный, рабочий, на русском языке.



Главное окно:



Название:

«Формирование плана склада»



Элементы:



\- поле выбранного Excel-файла;

\- кнопка «Сформировать план склада»;

5\. ВХОДНОЙ ФАЙЛ

==================================================



Пользователь каждый день берёт ВЧЕРАШНИЙ Excel-файл.



В нём остаётся вчерашний:



«План»



А два листа уже заменены свежими сегодняшними выгрузками:



«Заказы на отгрузку»

«Журнал заказов на отгрузку»



В книге могут находиться другие листы.



Другие листы:

НЕ удалять;

НЕ переименовывать;

НЕ менять;

НЕ переставлять.



«План» НЕ создавать заново.

Он обновляется на базе вчерашнего.

6\. ИСХОДНЫЙ ФАЙЛ НЕ ТРОГАТЬ

==================================================



Исходный файл никогда не перезаписывать.



После выбора файла:



создать копию в той же директории:



<исходное\_имя>\_готово\_YYYY-MM-DD\_HHMMSS.<ext>



Все изменения выполнять только над копией.



Обработка должна быть транзакционно безопасной.



Если возникает исключение:

\- корректно закрыть Excel;

\- не оставлять EXCEL.EXE;

\- не заменять исходник;

\- удалить/не оставлять повреждённый частичный результат;

\- показать пользователю ошибку.

7\. EXCEL COM

==================================================



Excel запускать скрыто:



Visible = false

DisplayAlerts = false



Не показывать пользователю служебные окна Excel.



После обработки:

пересчитать workbook.



Использовать нормальный Calculation mode.



КРИТИЧЕСКИ:

в finally корректно освободить ВСЕ COM objects.



Не должно оставаться zombie EXCEL.EXE.



Использовать:

Marshal.FinalReleaseComObject

где это необходимо.



Не использовать опасные цепочки COM-вызовов с временными неосвобождёнными объектами.

9\. ОБРАБОТКА В ПАМЯТИ

==================================================



Файлы могут быть большими.



Не ходить через Excel COM по каждой отдельной ячейке тысячи раз.



Считать UsedRange.Value2 в массивы.



Основную классификацию выполнять в памяти.



Использовать:

Dictionary<TKey,TValue>

HashSet<T>

List<T>



В Excel возвращать агрегированные изменения.



COM round-trips минимизировать.

10\. ФИЗИЧЕСКОЕ УДАЛЕНИЕ ОБРАБОТАННЫХ СТРОК

==================================================



На «Заказы на отгрузку» обработанные строки должны реально удаляться.



Это функциональное требование.



После завершения на листе остаются только строки:

\- не распределённые автоматически;

\- либо не подходящие под известные правила.



Они нужны для ручного контроля.



Удалять строки снизу вверх или безопасными диапазонами.



==================================================

11\. ОПТ

==================================================



Если «Подразделение» содержит без учёта регистра:



«Опт»



суммировать «разница единиц».



На «План»:



«заказы Опт»

→ «Количество единиц» = сумма.



Обработанные строки удалить.



Если строк Опт нет:

значение должно стать 0.



==================================================

12\. ИНТЕРНЕТ-МАГАЗИН

==================================================



Если «Подразделение» содержит:



«777»



SUM «разница единиц».



«заказы ИМ»

→ «Количество единиц» = SUM.



Строки удалить.



Если строк нет:

значение = 0.



==================================================

13\. МАРКЕТПЛЕЙСЫ

==================================================



Маркетплейс:



«Озон»

«ВБ»

«Ламода»

подразделение содержит «Сбер»

«Екатеринбург Яблоко»



Регистр игнорировать.



Обрабатывать строго в следующем порядке.



13.1 Возвраты



«Комментарий» содержит:



«возвр»



→ сумма «разница единиц»

→ «заказы МП» / «из возвратов»

→ удалить строки.



13.2 Из поставок



Для оставшихся маркетплейсов найти номер поставки.



Форматы:



1022-015

1244-001

МЗ806-133



Допускаются:

\- необязательные буквы перед цифрами;

\- кириллица;

\- латиница;

\- любой регистр.



Regex должен соответствовать правилу:



optional letters + digits + "-" + digits



Если найдено:

→ «заказы МП» / «из поставок»

→ SUM «разница единиц»

→ удалить.



13.3 Хранение



Все оставшиеся строки маркетплейсов:



→ «заказы МП» / «с хранилища и хранения»

→ SUM

→ удалить.



Это намеренное правило.



Не требуется отдельно распознавать A1/A2/A3.



Если по категории сегодня нет строк:

соответствующая сумма на «Плане» = 0.



==================================================

14\. СЛУЖЕБНЫЕ СТРОКИ

==================================================



После этого удалить любые оставшиеся строки, где «Комментарий» содержит:



«автозаказ»

«вирт»

«фото»



Регистр игнорировать.



Никуда не переносить.



==================================================

15\. НОМЕР ЗАГРУЗКИ

==================================================



Оставшиеся строки — кандидаты на реальные заказы.



Из «Комментарий» извлечь число после:



«Номер загрузки»



Регистр текста игнорировать.



Пример:



Срочная подтоварка 28.08\_Хранение, хранилище Номер загрузки 55575395 <Подбор:>



→ 55575395



Если номер не найден:

строку оставить на листе для ручной обработки.

Не удалять.



==================================================

16\. ГРУППИРОВКА

==================================================



Группировать оставшиеся корректные строки по номеру загрузки.



«Количество единиц» =

SUM «разница единиц».



«Дата документа» и комментарий можно брать из первого физического вхождения группы.



В нормальной выгрузке они одинаковые.



==================================================

17\. СНИМОК ВЧЕРАШНЕГО ПЛАНА

==================================================



ДО добавления новых заказов зафиксировать Set всех существующих:



«Номер загрузки»



из вчерашнего «Плана».



Это нужно для определения:

\- существующего заказа;

\- нового заказа;

\- новой поставки.



==================================================

18\. СУЩЕСТВУЮЩИЙ ЗАКАЗ

==================================================



Если номер загрузки уже есть:



обновить только:



«Количество единиц» = сегодняшняя сумма



плюс изменения, которые позже потребует «Журнал заказов на отгрузку».



«Группа»:

не трогать.



Заполненные существующие данные не перезаписывать без правила из ТЗ.



==================================================

19\. ИСЧЕЗНУВШИЙ СЕГОДНЯ ЗАКАЗ

==================================================



Если строка обычного заказа есть во вчерашнем «Плане», имеет номер загрузки, но сегодня этот номер среди обычных сегодняшних заказов отсутствует:



«Количество единиц» = 0.



Строку оставить.



==================================================

20\. НОВЫЙ ЗАКАЗ

==================================================



Если номера загрузки не было во вчерашнем Plan snapshot:



создать строку.



Если комментарий содержит:



«возвр»



→ блок «возвраты».



Остальные:

→ блок «все группы».



==================================================

21\. НОВАЯ СТРОКА — КОПИРОВАНИЕ ШАБЛОНА

==================================================



Новая строка должна быть визуально идентична существующим строкам соответствующего блока.



Не генерировать стили вручную.



Найти подходящую существующую DATA-строку внутри того же блока.



Вставить новую Excel row и использовать Excel Copy / PasteSpecial / formulas так, чтобы перенеслись:



\- formatting;

\- borders;

\- fills;

\- alignment;

\- row height;

\- number formats;

\- formulas;

\- conditional formatting behaviour.



Формулы должны сместиться так же, как при обычном копировании строки в Excel.



Не хардкодить формулу «Дата в сети».



Не хардкодить «Дата отгрузки».



Реальный Excel-файл — источник формул.



==================================================

22\. ЗАПОЛНЕНИЕ НОВОГО ЗАКАЗА

==================================================



«Поставки»:



скопировать часть исходного «Комментарий» от начала ДО:



«Номер загрузки».



Текст «Номер загрузки» и всё после него исключить.



Trim.



Пример:



Срочная подтоварка 28.08\_Хранение, хранилище Номер загрузки 55575395 <Подбор:>



→



Срочная подтоварка 28.08\_Хранение, хранилище



«Обработка»:



если заказ НОВЫЙ и в его тексте присутствует номер поставки:



1022-015

МЗ806-133

и аналогичный по заданному regex



→ «перекр».



Иначе:

пусто.



Не наследовать значение из строки-шаблона.



«Группа»:

пусто.



У существующих строк группу никогда не очищать.



«Комментарии»:



Заказы загружены.



«Дата документа»:

из сегодняшней выгрузки.



«Номер загрузки»:

из комментария.



«Количество единиц»:

сумма.



«статус»:

пусто.



«% выполнения»:

0\.



Формульные поля:

оставить формулами, скопированными из шаблонной строки.



Обычные данные другого заказа, случайно скопированные из template row:

очистить, если они не заданы этим ТЗ.



==================================================

23\. НОВАЯ ПОСТАВКА = «ПЕРЕКР»

==================================================



«Новая поставка» означает:



номер загрузки отсутствовал во вчерашнем Плане,

сегодня появился,

и в его комментарии/«Поставки» есть номер поставки.



Тогда:



«Обработка» = «перекр».



Существующим заказам автоматически «перекр» не добавлять.

==================================================



Искать подстроку:



«Сроч»



case-insensitive.



Для строк «Плана»:

в «Поставки».



Для сегодняшних заказов:

в исходном «Комментарий».



Таким образом определяются:

Сроч

Срочно

Срочная

Срочная подтоварка

и т. п.

25\. СЕТ / МОНО

==================================================



Искать в «Поставки»:



«СЕТ»

или

«МОНО»



case-insensitive.



СЕТ включает варианты:

СЕТ1

СЕТ2

и т. д.



Использовать для сортировки.



==================================================

26\. СТАРАЯ СТРОКА «ЗАКАЗЫ БУДУТ ЗАГРУЖЕНЫ»

==================================================



Если на «План» существует строка:



«Комментарии» содержит:

«Заказы будут загружены»



из её «Поставки» извлечь номер/номера поставки.



Если среди сегодняшних РЕАЛЬНЫХ заказов появилась строка с тем же номером поставки:



старую placeholder-строку удалить.



Сравнивать номера поставок.



==================================================

27\. ЖУРНАЛ

==================================================



Лист:



«Журнал заказов на отгрузку»



Для каждого реального заказа «Плана» с номером загрузки искать номер внутри колонки:



«Комментарий».



Физический порядок строк журнала является бизнес-значимым.



НЕ сортировать журнал.



Первое физическое вхождение = самое верхнее найденное.



==================================================

28\. НЕТ ЗАПИСИ В ЖУРНАЛЕ

==================================================



Если номер загрузки вообще не найден:



изменить только:



«Количество единиц» = 0.



Существующий status и % не менять.



У новой строки:

status останется пустым,

% останется 0.



==================================================

29\. ПЕРВОЕ ВХОЖДЕНИЕ: % > 0

==================================================



Если % первого физического вхождения > 0:



Plan:



«статус» = «в сборке»



«% выполнения» = % первого вхождения.



Если % = 100:

статус всё равно «в сборке».



==================================================

30\. ПЕРВОЕ ВХОЖДЕНИЕ: % = 0

==================================================



Если первое % = 0:



посмотреть все остальные вхождения того же заказа.



Если хотя бы одно имеет:



Статус = «Запущен»



case-insensitive:



«статус» = «в сборке».



% НЕ обнулять специально.



Существующий заказ:

оставить прежний %.



Новый:

0\.



Если первое % = 0 и нигде нет «Запущен»:



существующий заказ:

статус и % оставить вчерашними.



новый заказ:

статус пусто,

% = 0.



==================================================

31\. АВТОЗАКАЗЫ ДЛЯ ХАБОВ

==================================================



Найти строку:



«автозаказы для хабов».



По текущему local date Windows:



Monday = 24000

Tuesday = 18000

Wednesday = 12000

Thursday = 6000

Friday = 42000



Saturday / Sunday:

значение «Количество единиц» не менять.



Не вычислять собственный интервал до пятницы.



==================================================

32\. СОРТИРОВКА

==================================================



Приоритизировать DATA-строки внутри:



«все группы»

«приемка на хранилище».



Не смешивать блоки.



Не перемещать section headers.



Для «все группы»:



1-я DATA строка всегда:

«Приемка на хранилище»



2-я DATA строка всегда:

«автозаказы для хабов»



Остальные:



сначала срочные,

затем несрочные.



В каждой категории:

«Дата в сети» ascending.



Дата ВАЖНЕЕ СЕТ/МОНО.



Пример:



01.09 МОНО

02.09 СЕТ

СЕТ выше МОНО.

срочность → дата → при одинаковой дате СЕТ до МОНО.



«возвраты»:

Excel.Calculate / workbook calculation,
